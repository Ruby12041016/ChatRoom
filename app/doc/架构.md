## 通信流程示例（登录）

```
用户输入 → cli_menu → cli_account::Login(acc,pwd)
  → cli_network 发送 TCP 包 (4字节长度+JSON)
  → 服务端 server::MainReactor 接收
  → WorkerPool 线程解析 → MessageRouter
  → AccountHandler::handle_login
    → 查询 MySQL 验证密码
    → 写入 Redis 在线状态
    → send_ok(conn, MSG_LOGIN, user_data)
  → TCP 返回 JSON 响应
  → 客户端 cli_network 接收 → 放入消息队列
  → cli_menu::ProcessMessages 分发
  → cli_account::OnLoginResponse 更新 Session，通知回调
  → 打印“登录成功”并切换主菜单
```

## 关键设计决策

- **服务端不信任客户端**：所有权限校验（好友关系、群成员）在服务端 Handler 中完成。
- **离线消息**：私聊/群聊消息存入 MySQL，用户上线时查询 `status=0` 的记录并推送，然后标记为已读。
- **在线状态**：仅通过 Redis Set 维护，心跳续期，客户端不直接接触 Redis。
- **文件传输**：文件 Base64 编码后走消息通道，服务端解码存储。
- **并发模型**：服务端采用主从 Reactor + 线程池；客户端单线程异步回调。
