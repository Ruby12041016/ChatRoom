# 两种绑定区别

两个“绑定”虽然操作的都是同一个 `user_id`，但它们发生在**完全不同的层面**，扮演着**两个截然不同的角色**。

为了方便理解，可以把它们想象成现实中的 **“身份证”** 和 **“酒店前台登记本”**。

---

### 1. `conn->setUserId(uid)` —— 内部绑定（授予“身份证”）
*   **发生层面**：**TCPConnection 对象自己内部**（内存）。
*   **作用**：**身份自证**。告诉这条连接：“现在的你是用户 A”。
*   **结果**：只有这条 TCP 连接自己知道自己是 A。每次收到客户端发来的请求时，业务逻辑通过 `conn->getUserId()` 拿到这个 ID，用于判断 **“谁发的请求”**。
*   **关键点**：如果不去调用 `setUserId(0)`，这条连接就会一直认为自己是 A（即便管理器删掉了，它自己还不知道）。

### 2. `ConnectionManager::Add(uid, conn)` —— 外部绑定（酒店前台“登记本”）
*   **发生层面**：**全局管理器中**（一个巨大的哈希表）。
*   **作用**：**对外寻址**。告诉服务器：“用户 A 的房间号是 101（这个 TCP 连接）”。
*   **结果**：当服务器有消息要推送给用户 A 时（例如别人给 A 发私信，或者同意 A 的好友申请），会**通过 `manager.GetConnByUserId(uid)` 查这个表**，找到对应的连接，然后把消息发过去。
*   **关键点**：如果没做这一步，就算 `conn` 自己知道自己是谁，其他业务逻辑也找不到它，没法给 A 发消息。

---

### 3. 核心对比

| 对比维度 | **内部绑定 (`setUserId`)** | **外部绑定 (`ConnectionManager::Add`)** |
| :--- | :--- | :--- |
| **数据结构** | 连接内部的成员变量 `uint64_t user_id_` | 全局的单例哈希表 `unordered_map` |
| **调用时机** | 登录成功后，**首先执行** | 登录成功后，**接着执行** |
| **生命周期** | 跟随连接自身的生命周期 | 跟随服务器全局的生命周期 |
| **主要用途** | 业务逻辑校验权限 (`isLogin()`)、获取发件人 | 接收推送通知 (`GetConnByUserId()`)、踢人下线 |
| **关系性质** | **强关联**（自己死盯着自己的 ID） | **弱引用**（`weak_ptr`，不干扰连接析构） |
| **失败后果** | `isLogin()` 永远返回 false，业务无法执行 | 别人发不了消息给该用户，推送落空 |

---

### 它们是如何配合导致“连接泄漏”的？
如果**漏了**其中一步，就会引发大麻烦：

*   **只有 1，没有 2** : 用户登录了，自己知道自己是 A，但是**别人发消息给他时，服务器找不到他的连接**（推送失败）。
*   **只有 2，没有 1** : 管理器里登记了 A 是 101 房间，但是 101 房间的门牌（`user_id_`）没贴上！当业务逻辑要处理 101 的请求时，`conn->getUserId()` 返回 0，直接判定为 **“未登录”**，把请求全拦截了。

---

### 4. 它们的黄金搭档（登录成功时的代码逻辑）

登录逻辑是这样的（两者缺一不可）：

```cpp
void AccountHandler::handle_login(...) {
    // ... 校验密码成功 ...
    uint64_t user_id = 1001;

    // 第一步：内部绑定（给连接“发身份证”）
    conn->setUserId(user_id); 
    
    // 第二步：外部注册（在前台“登记”）—— 用弱指针包装好
    ConnectionManager::GetInstance().Add(user_id, conn); 

    send_ok(conn, MSG_LOGIN, {});
}
```
---
### 5. 补充
函数 `bool isLogin() const { return user_id_ != 0; }`。
这证明了**内部绑定**是绝对的权威。就算程序刚启动时 **`ConnectionManager` 里的表是空的**，只要 `conn->setUserId(1001)` 执行了，`isLogin()` 就一定会返回 `true`。它是自我认知的基础，**底层是它，对外寻址是管理器**。

**总结一句话**：`setUserId` 是给自己看的（证明我是谁），`Manager::Add` 是给别人看的（方便别人找到我）。两者缺一不可！
