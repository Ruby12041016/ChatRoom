# 密码存储（PBKDF2-HMAC-SHA256）
## 一、为什么不能存储明文密码
若数据库泄露：
```
username      password
tom           123456
alice         admin123
```
攻击者可直接拿到用户原始密码登录账号。

**核心准则：数据库绝对不能保存明文密码。**
正确流程：
原始密码 → Hash摘要 → 存入数据库
数据库只保存密码摘要，不保存原始密码。

## 二、什么是Hash（哈希）
Hash是**单向密码学函数**，关键特性：
1. 输入确定，输出长度固定
2. **不可逆**，无法从摘要反推原始内容
3. 输入微小改动，输出完全不同

示例：
```
123456 → SHA256 → 8d969eef6ecad3...
123457 → SHA256 → 完全不同的字符串
```

## 三、为什么不能直接使用SHA256
错误写法：
```cpp
hash = SHA256(password);
```
存在两大风险：
1. 相同密码会生成完全一致哈希，数据库中一眼就能看出哪些用户密码相同
2. 攻击者可使用**彩虹表、字典攻击**快速批量破解

结论：**单纯直接Hash不安全**。

## 四、Salt（盐值）
Salt：为每个用户**独立随机生成的字符串**。

运算逻辑：`原始密码 + Salt → Hash`
数据库同时存储：hash值、salt值。

作用：
即使多名用户原始密码一样，搭配不同Salt后，最终哈希结果完全不同。
抵御：彩虹表攻击、相同密码哈希碰撞。

## 五、SHA256 + Salt 依旧存在安全缺陷
SHA256算法运算速度极快，现代GPU每秒可完成数十亿次SHA256计算。
攻击者可以持续穷举密码、不断计算哈希进行比对，暴力破解成本很低。

## 六、PBKDF2 算法
PBKDF2（Password-Based Key Derivation Function 2）：基于密码的密钥派生函数，专门用于密码存储。
核心特点：
- 支持自定义迭代次数，多次重复运算
- 人为降低运算速度，提升破解成本
- 标准成熟、兼容性好

运算流程：
原始密码 + Salt → HMAC-SHA256 → 重复迭代N次 → 最终密码摘要

攻击者每尝试猜测一个密码，都需要完整执行N次HMAC运算，暴力破解开销大幅上升。

## 七、为什么选用 HMAC-SHA256
PBKDF2底层并非直接调用SHA256，而是 **HMAC-SHA256**。
HMAC全称：基于哈希的消息认证码（Hash-based Message Authentication Code）。
相比原生SHA256，抗攻击能力更强。
OpenSSL中 `EVP_sha256()` 可提供该算法实现。

## 八、项目固定参数配置
```cpp
constexpr int SALT_LEN = 16;    // Salt：16字节 = 128bit
constexpr int HASH_LEN = 32;    // 输出哈希：32字节 = 256bit
constexpr int PBKDF2_ITER = 100000; // 迭代次数10万次
```
属于工程中通用、平衡性能与安全的配置方案。

## 九、注册完整流程
1. 用户客户端提交原始密码
2. 服务器使用安全随机接口生成独立Salt
3. 执行 PBKDF2-HMAC-SHA256 计算得到密码哈希
4. 将 `用户名、password_hash、salt` 存入数据库
>  数据库**绝不存储原始密码**

## 十、登录完整流程
1. 用户输入密码提交服务端
2. 根据用户名查询数据库，取出该用户对应的salt与password_hash
3. 使用输入密码 + 数据库salt，执行相同参数的PBKDF2运算，得到新哈希
4. 将新哈希与库中存储的哈希进行对比
5. 哈希一致 → 登录成功；不一致 → 登录失败

## 十一、重要概念：哈希 ≠ 加密
加密存在对应的解密算法，可以还原原文；
哈希是单向运算，**不存在解密函数**。

数据库泄露后，攻击者无法通过哈希逆向算出原始密码，只能不断猜测密码进行穷举验证。

## 十二、恒定时间比较 Constant-Time Compare
普通字符串比较：
```cpp
if(hash1 == hash2)
```
默认是**短路比较**：只要遇到第一个不相同字节，立刻终止判断。

攻击者可以利用**时序攻击（Timing Attack）**：根据请求耗时长短，推断哈希前多少字节匹配，逐步破解。

解决方案：实现 `secure_compare()`
完整遍历所有字节进行对比，无论在哪一个位置出现差异，执行耗时基本一致，消除时序漏洞。

## 十三、数据库表设计
```sql
CREATE TABLE user
(
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(32) UNIQUE NOT NULL,
    password_hash CHAR(64) NOT NULL,
    salt CHAR(32) NOT NULL,
    create_time BIGINT NOT NULL
);
```
说明：
- PBKDF2输出32字节二进制哈希 → 转为Hex十六进制字符串，占用64个字符
- Salt为16字节二进制 → 转为Hex，占用32个字符

## 十四、为什么要使用Hex编码保存
PBKDF2直接输出原始二进制字节流，不方便直接存入MySQL；
将二进制转换成Hex字符串进行持久化。
校验时，再把Hex字符串还原成二进制字节数组参与运算。

## 十五、OpenSSL 相关API
1. 生成密码学安全随机Salt：`RAND_bytes()`
2. PBKDF2核心函数：`PKCS5_PBKDF2_HMAC()`
3. 指定哈希算法：`EVP_sha256()`

## 十六、整套密码存储方案流程图
### 注册流程
```
用户密码
    │
    ▼
生成随机Salt
    │
    ▼
PBKDF2-HMAC-SHA256 运算
    │
    ▼
得到密码哈希
    │
    ▼
数据库保存：username、password_hash、salt、create_time
```

### 登录验证流程
```
用户输入密码
    │
    ▼
查询数据库，取出 password_hash、salt
    │
    ▼
PBKDF2(输入密码, salt) 计算本地哈希
    │
    ▼
恒定时间安全比对两个哈希
    │
    ▼
匹配成功 / 验证失败
```

## 时间戳工具 get_timestamp_sec /get_timestamp_ms
```cpp
uint64_t get_timestamp_sec()
{
    // 获取当前系统时间，换算成从1970-01-01至今的总秒数
    auto now = std::chrono::system_clock::now();
    auto sec = std::chrono::duration_cast<std::chrono::seconds>(now.time_since_epoch());
    return sec.count();
}
```
用途：
1. 验证码设置 5 分钟过期：当前秒戳 + 300，用户提交时对比时间戳判断是否过期
2. 每条聊天消息附带时间戳，客户端按时间排序聊天记录

## 说明
1. SHA256 加密需要系统加密库 OpenSSL
2. 注册时：生成随机盐 → 明文 + 盐 SHA256，数据库同时存 
3.  登录时：取出数据库盐值，用输入密码 + 盐再次加密，对比哈希值。
4. 拦截特殊符号、空格、中文，防止 SQL 注入、JSON 解析异常、缓冲区越界崩溃；
5. 使用 std::random_device 真随机，不使用不安全的 rand()；
6. 时间戳可用于消息创建时间、验证码过期计时、离线消息时效判断。
